Q02Hybrid RetrievalHard
Your RAG system uses hybrid retrieval on BBVA's financial corpus. A query for 'Article 7, Section 3(b)' returns completely wrong results from vector search. Why does this happen and what does hybrid retrieval add?
AVector search fails on exact regulatory references because embedding models rarely encounter alphanumeric clause identifiers in training data, so these codes receive poorly separated embeddings. BM25 exact-matches them precisely via inverted index term frequency, and RRF combines both ranked lists without score normalisation
BThe issue is approximate nearest-neighbour search — FAISS-based ANN search trades accuracy for speed, and short exact reference queries fall in the tail of the approximation error. Switching to exact k-NN search (brute force) resolves clause reference retrieval without needing a lexical component
CThe embedding model's tokeniser splits 'Section 3(b)' into subword tokens that don't preserve the clause identifier as a unit, so the vector representation drifts toward generic 'section' meaning. Upgrading to a tokeniser with whole-word masking fixes this without needing BM25
DVector search uses cosine similarity which penalises short queries — 'Article 7, Section 3(b)' is too short to produce a high-magnitude embedding, causing low similarity scores across all documents. Padding the query with related financial context terms improves retrieval without hybrid search
Q03Re-rankingMedium
You added a cross-encoder reranker after bi-encoder retrieval. A colleague says skipping re-ranking and retrieving top-3 directly is equivalent since the bi-encoder already identifies the best documents. What is the specific flaw in this reasoning?
ABi-encoders encode query and document independently, producing approximate similarity scores — the actually most relevant document may rank 8th, not 1st. Retrieving only top-3 permanently discards it; a cross-encoder seeing all 20 candidates jointly would have promoted it.
BTop-3 retrieval is actually more accurate than top-20 with reranking because precision increases as k decreases — with fewer candidates, both the bi-encoder and cross-encoder make fewer errors, so the narrower retrieval is inherently more reliable
CThe flaw is computational — retrieving top-3 uses the same index scan as top-20 but skips the reranker, creating a false economy since the bi-encoder's embedding computation is the expensive step, not the reranker
DThe reasoning is correct for most queries but breaks down when the corpus has duplicate documents — without reranking, top-3 may contain three versions of the same document, while a reranker trained on diversity criteria would ensure varied coverage
Q04Chunking for Legal DocsHard
Your BBVA loan agreement PDF has numbered clauses. Fixed 512-token chunking splits clause 7.3.2 across two chunks. Which strategy preserves clause integrity, and what trade-off must you manage?
AStructural chunking splits at document hierarchy boundaries (section → clause) rather than fixed token counts, preserving clause 7.3.2 as one unit. The trade-off is variable chunk sizes — short one-line clauses produce low-information embeddings and long sections exceed embedding model max length, requiring parent-child chunking to balance precision with context
BSentence-level chunking splits at each sentence boundary, guaranteeing that no clause is divided mid-sentence. The trade-off is that multi-sentence clauses lose cross-sentence dependencies, and the granularity is too fine for embedding models to capture clause-level semantics
COverlapping chunks with 50% token overlap ensure clause 7.3.2 always appears complete in at least one chunk since the split point falls within the overlap region. The trade-off is doubled storage and doubled embedding computation cost for the entire corpus
DRecursive character text splitting with progressively smaller separators (paragraph → sentence → word) attempts hierarchy-aware splitting without a parsed document structure. The trade-off is that it requires no document parsing but cannot guarantee clause boundaries are respected when separators don't align with legal clause markers
